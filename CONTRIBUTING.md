# Contributing

Thanks for helping improve QaceFlow.

1. Create a focused branch for your change.
2. Keep changes small and explain their purpose in the commit message.
3. Add tests for detection, correlation, persistence or API behavior changes.
4. Run backend tests and `npm run build` before opening a pull request.
5. Do not include credentials, real user telemetry, `.venv`, `node_modules`, databases, caches or generated build output.
6. Label synthetic data clearly and avoid describing candidate incidents as confirmed breaches.
